SignalFlow is an AI-native revenue operating system that turns customer signals into governed, auditable, revenue-generating actions.

> SignalFlow is a deterministic demo platform. No live calls, SMS, email, AI provider calls, or real customer data are used. Every output is generated by deterministic engines and internal mock providers.

## What SignalFlow demonstrates

SignalFlow models the gap between a customer signal and a revenue action. A trade-in request, missed call, overdue recall, or policy review can create revenue, but traditional CRMs often wait for a human to notice. SignalFlow shows how an AI-native workflow can detect intent, apply policy, route sensitive decisions through human review, simulate follow-up, and attribute the outcome.

The platform demonstrates:

- Customer signal capture and intelligence modeling
- Intent, opportunity, and engagement scoring
- Governed AI recommendations with confidence and explanations
- Human review for sensitive recommendations and voice plans
- Consent-aware workflow simulation
- Voice follow-up simulation with compliance checks
- Provider governance with feature flags and readiness gates
- Outcome tracking and revenue attribution
- Multi-tenant, organization-scoped architecture
- Audit trails for decisions, actions, provider checks, and outcomes

## Hiring manager quick read

SignalFlow is designed as a production-shaped proof-of-work. It is intentionally demo-safe, but the architecture mirrors patterns used in enterprise AI systems:

- Pages render UI and call services
- Services compose business logic
- Repositories own database access
- Pure engines hold deterministic domain logic
- Provider use is gated through registry, feature flags, readiness checks, and audit events
- Sensitive recommendations are routed through human review
- External providers are modeled, but not called

The repo is strongest as evidence for roles involving AI workflow systems, full-stack product engineering, solutions engineering, technical product work, implementation architecture, and governed AI applications.

## What is not integrated

SignalFlow does not make live calls to OpenAI, Anthropic Claude, Google Gemini, Azure OpenAI, OpenAI Realtime, ElevenLabs, Twilio, Retell, Vapi, or SendGrid.

Those providers are represented as future-ready registry entries only. The active implementation uses deterministic internal mock providers for AI, voice, SMS, and email.

## Architecture overview

SignalFlow follows a layered architecture:

```text
Page
  to Service
  to Repository
  to Prisma
  to PostgreSQL
```

Pure engines for intelligence, scoring, action graph, workflow, outcomes, AI, voice, providers, and feature flags do not import React, Prisma, Clerk, Next.js, repositories, or provider SDKs.

These rules are enforced by:

- `scripts/check-architecture-boundaries.ts`
- `scripts/scan-safety.ts`

## Demo safety boundaries

SignalFlow is intentionally network isolated and deterministic:

- No live SMS, email, or voice
- No AI provider calls
- No provider SDKs installed
- No outbound network calls
- No real secrets stored
- No real customer data
- Internal mock providers only

These boundaries are documented and verified through repository scans.

Requirements:

- Node.js 18.18 or later


Apply migrations and seed deterministic demo data:

```bash
npm run db:migrate
```

Run the app:

```bash
npm run dev
```

Open:

```text
http://localhost:3000
```

## Production readiness boundary

SignalFlow is not presented as a live production SaaS system. It is a deterministic architecture and governance proof-of-work.

Before production use, the next major work would include:

- Real provider adapters behind the existing provider interfaces
- Secret manager integration
- Production observability and alerting
- Background jobs and queues
- Rate limiting
- Load testing
- Expanded service and repository tests with a real test database
- Expanded authorization tests
- Deployment-specific CSP validation
- Operational runbooks
- Customer data handling policies
