# SignalFlow

An AI-native revenue operating system that turns customer signals into governed, auditable, revenue-generating actions.

> SignalFlow is a deterministic demo platform. No live calls, SMS, email, AI provider calls, or real customer data are used. Every output is generated by deterministic engines and internal mock providers.

## What it is in one sentence

SignalFlow reads customer signals, builds a customer intelligence graph, generates governed AI recommendations, routes them through human review, simulates multi-channel and voice follow-up, and attributes the revenue outcome, all on a multi-tenant, organization-scoped foundation.

## The product problem

Revenue teams lose money in the gap between a signal and an action. A trade-in request, a missed call, an overdue recall, or an expiring policy arrives, and nothing happens until a person remembers to follow up. Traditional CRMs make this worse:

- They store records and wait for a human to decide what happens next.
- Activity is logged after the fact instead of driving the next action.
- Consent and compliance live in scattered fields, not an enforced policy layer.
- Channels are siloed, so SMS, email, and voice rarely act as one coordinated follow-up.

## What SignalFlow does

SignalFlow is built to decide and act, with governance at the center:

- Captures customer signals and builds a deterministic customer intelligence graph.
- Scores intent, opportunity, and engagement, and detects revenue opportunities.
- Generates AI recommendations with a confidence score and a full explanation.
- Routes recommendations and sensitive voice plans through a human review queue.
- Plans and simulates multi-channel and voice follow-up behind a consent and compliance policy layer.
- Records outcomes, advances opportunity stages, and attributes revenue.
- Audits every decision and action, organization by organization.

## Architecture overview

SignalFlow uses a layered architecture with strict boundaries. Pages render, services compose business logic, repositories own all database access, and pure engines hold deterministic domain logic with no framework dependencies.

```text
Page (presentation)
  to Service (business logic and composition)
  to Repository (organization scoped data access)
  to Prisma
  to PostgreSQL
```

Pure engines (intelligence, scoring, action graph, workflow, outcomes, AI, voice, providers, feature flags) import no React, no Prisma, and no auth client. Text-based diagrams for every lifecycle are in [docs/ARCHITECTURE_OVERVIEW.md](docs/ARCHITECTURE_OVERVIEW.md), and a staff-level breakdown is in [docs/TECHNICAL_HIGHLIGHTS.md](docs/TECHNICAL_HIGHLIGHTS.md).

## Core platform capabilities

- Customer intelligence graph and deterministic signal engine
- Opportunity detection and next best action
- AI recommendation governance with confidence, explanation, and a human review queue
- Action graph, workflow engine, and a consent and compliance policy layer
- Outcome memory and revenue attribution
- Vertical packs, a scenario builder, and a simulation center
- Revenue Command Center with a per-customer mission replay
- Voice simulation platform with voice compliance and voice replay
- Provider registry, capability matrix, feature flag framework, readiness checks, and a provider sandbox
- Multi-tenancy, role based access control, and an end to end audit trail

## Tech stack

- TypeScript with Next.js App Router and React server components
- Tailwind CSS with a small shadcn-style component library
- PostgreSQL with Prisma as the source of truth
- Clerk as an optional authentication provider with a deterministic demo fallback
- A repository and service architecture with pure deterministic domain engines

## Demo safety boundaries

SignalFlow is intentionally network isolated and deterministic:

- No live SMS, email, or voice. Nothing is sent.
- No AI provider calls. AI output comes from deterministic engines and internal mock providers.
- No provider SDKs are installed, and no provider API is called.
- No outbound network calls are made.
- No secrets are stored. Required provider secrets are documented as placeholder names only.
- No real customer data. All data is generated by the seed script.

These boundaries are enforced in code and verified by repository scans. See [docs/REPO_QUALITY_CHECKLIST.md](docs/REPO_QUALITY_CHECKLIST.md).

## Local development

Requirements: Node.js 18.18 or later and a local PostgreSQL instance.

### 1. Install dependencies

```bash
npm install
```

### 2. Configure the database connection

Copy the example environment file and set `DATABASE_URL` to point at your local PostgreSQL database.

```bash
cp .env.example .env
```

The default value targets a local database named `signalflow`:

```
DATABASE_URL="postgresql://signalflow:signalflow@127.0.0.1:5432/signalflow?schema=public"
```

This value is a local development convenience, not a secret. The `.env` file is gitignored and no credentials are committed.

### 3. Apply migrations and seed demo data

```bash
npm run db:migrate    # apply migrations and generate the Prisma client
npm run db:seed       # load the deterministic demo data
```

### 4. Run the app

```bash
npm run dev
```

Then open http://localhost:3000.

## Validation commands

```bash
npm run typecheck         # typescript without emit
npm run lint              # eslint
npm run test              # vitest unit tests for the pure engines
npm run scan:safety       # fail on banned content, secrets, network calls, SDKs
npm run check:architecture # enforce page, service, repository, engine boundaries
npx prisma validate       # validate the schema
npx prisma migrate status # confirm migrations are applied
npm run build             # production build
```

These same steps run in continuous integration on every push and pull request
through `.github/workflows/ci.yml`. See [docs/ENGINEERING_QUALITY.md](docs/ENGINEERING_QUALITY.md).

Useful scripts:

```bash
npm run db:generate  # generate the Prisma client
npm run db:migrate   # create and apply a migration in development
npm run db:reset     # drop, recreate, migrate, and reseed the database
npm run db:seed      # seed demo data
npm run db:studio    # open Prisma Studio
```

## Recruiter-friendly summary

SignalFlow is a deterministic, demo-safe AI revenue platform that demonstrates staff-level architecture: domain-driven design with strict page, service, repository, and engine boundaries; organization-scoped multi-tenancy with role based access control; an AI recommendation layer governed by human review; a simulated voice platform with a deterministic compliance engine; and a provider governance layer with feature flags and readiness gates that keep every external provider safely disabled. It is built with TypeScript, Next.js, PostgreSQL, and Prisma. A condensed summary for recruiters and hiring managers is in [docs/PORTFOLIO_SUMMARY.md](docs/PORTFOLIO_SUMMARY.md).
